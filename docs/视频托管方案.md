# 视频托管方案：录好之后放哪里

> 结论先说：**不要把视频文件放进 Git 仓库。**
> GitHub Pages 有 1GB 站点上限、软性 100GB/月流量限制，
> 而且大文件进 Git 历史后**永久无法真正删除**（除非重写历史）。
> 几分钟的录屏就能把这个博客撑爆。

---

## 一、为什么不能直接放仓库里

| 限制 | 具体值 | 后果 |
|---|---|---|
| 单文件 | GitHub 硬限制 **100MB** | 一个 10 分钟的 1080p 录屏轻松超过 |
| 仓库建议上限 | 1GB | 放 3~4 个视频就接近 |
| Pages 流量 | 软性 **100GB/月** | 一个 500MB 的视频被看 200 次就爆 |
| Git 特性 | 每个版本都完整保存 | 删除文件后历史里依然占空间 |
| 播放体验 | 不支持 HTTP Range 优化 | 拖动进度条会卡、无法边下边播 |

最后一条是很多人忽略的：视频播放需要**分段请求（HTTP Range）**，
浏览器才能跳转进度。静态托管的支持程度参差不齐，体验会很差。

---

## 二、五条可行路线

### 方案 A：B 站 / 视频平台嵌入

录好上传到 B 站，文章里嵌入播放器。

**优点**
- 零成本，零运维
- 平台负责转码、多种清晰度、CDN 分发
- 国内访问速度有保障
- 自带弹幕/评论（对你可能算优点也可能算缺点）

**缺点**
- 片头广告（B 站现在有）
- 视频不在你手里，平台删了你的站上就是空白
- 读者要跳出去，跳出率上升
- 播放器界面是平台的，跟博客风格不搭

**适合**：以内容传播为主要目的、不在意品牌一致性的情况。

---

### 方案 B：Cloudflare R2（推荐给自建路线）

对象存储，**出站流量免费**是这个方案最大的优势。

**优点**
- **出流量 0 费用**（写入和存储收费，但便宜）
- 可绑自己的域名，URL 干净
- 支持 HTTP Range，播放体验好
- 可以用 Cloudflare 的 CDN 加速

**费用参考**（文章写作时的定价，以官网为准）
- 存储：$0.015 / GB / 月
- A 类操作（写）：$4.50 / 百万次
- B 类操作（读）：$0.36 / 百万次
- **出站流量：免费**

**缺点**
- 国内访问速度一般（Cloudflare 免费版在国内没有优质节点）
- 需要自己上传、自己管理
- 视频**不转码**，你得自己压好

**适合**：愿意折腾、视频量不大、能接受国内速度一般的情况。

---

### 方案 C：阿里云 OSS / 腾讯云 COS

国内对象存储，速度最好。

**优点**
- 国内访问速度最快
- 生态成熟，工具多

**缺点**
- **要钱**：存储 + 流量都要付费，流量是大头
- 绑定自定义域名做 CDN 加速**需要域名已备案**
- 默认域名访问视频会带 `Content-Disposition: attachment`，
  也就是**直接变成下载而不是播放**，要额外配置

**适合**：已经有备案域名、预算充足、对国内速度要求高。

---

### 方案 D：自建（你已经有 Tailscale）

放在自己机器或 NAS 上，通过 Tailscale / 内网穿透访问。

**优点**
- 完全自主，零边际成本
- 想放多少放多少（受限于硬盘）

**缺点**
- **只有能连上你内网的人能看** —— 公开博客的读者看不了
- 家用上传带宽通常很小（很多是 30Mbps 上行），
  几个人同时看就卡
- 机器关机 = 视频全挂

**适合**：视频只给特定的人看（团队内部、自己存档），不适合公开博客。

> 顺带说：你机器上有 Tailscale 安装包。如果视频是**内部演示**性质，
> 这条路很合适；如果是给公开读者的，不行。

---

### 方案 E：YouTube / Vimeo

**优点**：免费、体验好、自动转码、支持多清晰度
**缺点**：**国内打不开**，读者需要梯子

**适合**：读者主要在海外。

| | 费用 | 国内速度 | 自主可控 | 播放体验 | 运维成本 |
|---|---|---|---|---|---|
| A. B 站嵌入 | 免费 | 好 | 差 | 好 | 极低 |

## 四、我的建议

**分两步走，不要一开始就追求完美。**

**第一步（现在）**：视频先用 **B 站嵌入**。
理由很简单 —— 你还没开始录。先解决"能放上去"，
把精力花在内容上。等积累了几个视频、确认这件事能持续做下去，
再考虑迁移。

**第二步（如果值得）**：迁到 **Cloudflare R2**。
R2 的出流量免费，意味着视频被看多少次都不心疼。
而且 URL 可控、能绑自己域名。

**不推荐**：一开始就上阿里云 OSS + 备案。除非你确定视频会有大的访问量，
否则备案的时间成本和流量费用都不划算。

## 五、怎么在文章里放视频

站点已经内置了 `Video` 组件，**两种模式都支持**，
所以现在用 B 站、以后换 R2 都不用改文章结构。

在 `.mdx` 文件里（注意：**必须是 `.mdx`，不能是 `.md`**，因为要引入组件）：

```mdx
---
title: '文章标题'
pubDate: 2026-04-08
---

{/* 路径深度：文章在 src/content/posts/<板块>/ 下，是三层深，所以是 ../../../ */}
import Video from '../../../components/Video.astro';

{/* 模式一：B 站嵌入 */}
<Video
  embed="https://player.bilibili.com/player.html?bvid=BVxxxxxxxxxx&autoplay=0"
  title="用 Wireshark 定位一次丢包问题"
  duration="12:34"
  caption="录制于 2026 年 4 月，环境为 Ubuntu 24.04"
/>

{/* 模式二：直链播放（R2 / OSS / 自建） */}
<Video
  src="https://video.example.com/wireshark-demo.mp4"
  poster="/videos/wireshark-demo-cover.jpg"
  title="用 Wireshark 定位一次丢包问题"
  duration="12:34"
  caption="1080p，建议全屏观看"
/>
```

**两个容易踩的坑**（都实际遇到过）：

1. **忘了 import**。报错是 `Expected component 'Video' to be defined`，
   不是"找不到模块"，容易往错误方向查。
2. **import 路径深度写错**。文章在 `src/content/posts/<板块>/` 下是三层深，
   必须 `../../../components/`。写成 `../../` 会报 `UNRESOLVED_IMPORT`。

可以照 `src/content/posts/tech/video-demo.mdx` 抄，
那份是草稿状态，专门用来确认版式。

组件特性：
- `preload="none"`，不预加载视频，不白耗读者流量
- `playsinline`，iOS 上不会强制全屏
- `aspect-ratio` 保持画面比例，加载前就占好位，**不会造成布局跳动**
- `loading="lazy"` 嵌入模式懒加载
- 支持封面图，避免首帧黑屏

## 六、录制前就该定下来的三件事

这三条如果录完再改，就得重录：

**① 分辨率与帧率**

| 内容类型 | 建议 |
|---|---|
| 纯终端 / 代码演示 | 1920×1080，**30fps 足够**，字要够大 |
| 界面操作 | 1920×1080，30fps |
| 需要展示动效 | 1920×1080，60fps |

终端录屏**千万别用 60fps** —— 文件大一倍，而画面几乎不变。
另外**把终端字号调到 16pt 以上**，否则压完之后看不清。

**② 音频**

绝大多数教程视频毁在音频上，不是画质。
- 用**独立麦克风**，别用笔记本内置的
- 录之前测 10 秒，回放听有没有电流声和键盘声
- 环境噪音比设备档次影响更大

**③ 视频长度**

单个视频**控制在 10 分钟以内**。
超过 20 分钟的，拆成几集。
理由：长视频的文件体积、上传时间、观众完成率都更差。

## 七、压缩（上传前必做）

原始录屏文件极大（10 分钟可能 1GB+）。用 ffmpeg 压：

```bash
# 1080p 屏幕录制：CRF 23 是画质与体积的较好平衡
ffmpeg -i raw.mp4 -c:v libx264 -preset slow -crf 23 \
       -vf "scale=1920:-2" -c:a aac -b:a 128k out.mp4

# 如果画面静态内容多（终端、PPT），可以加长关键帧间隔，体积更小
ffmpeg -i raw.mp4 -c:v libx264 -preset slow -crf 26 \
       -g 300 -c:a aac -b:a 96k out.mp4

# 生成封面图（取第 10 秒那一帧）
ffmpeg -ss 00:00:10 -i out.mp4 -frames:v 1 -q:v 3 cover.jpg
```

`-crf` 是画质参数，**数值越小越清晰、文件越大**：
- 18 = 视觉无损，文件大
- 23 = 默认值，推荐
- 26~28 = 静态画面多的内容够用

**你的机器上已经有 ffmpeg**（在 Downloads 里那个 ffmpeg-master 目录），
不用另外装。
