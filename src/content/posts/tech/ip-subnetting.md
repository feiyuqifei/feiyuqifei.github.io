我见过很多人能背出这张表：

| 掩码 | 位数 | 可用主机数 |
|---|---|---|
| 255.255.255.0 | /24 | 254 |
| 255.255.255.128 | /25 | 126 |
| 255.255.255.192 | /26 | 62 |

然后一到实际规划就开始出错：网关配错、网段重叠、
可用地址算少两个、或者把网络地址配到了设备上。

**背表和会算是两回事。** 这篇不讲速记技巧，
而是从一个规划需求出发，把每一步的计算过程摊开。

## 一、先把三个概念钉死

很多错误源于这三个东西混在一起：

- **网络地址**：主机位全 0，代表"这个网段本身"，**不能配给设备**
- **广播地址**：主机位全 1，代表"这个网段里所有人"，**不能配给设备**
- **可用地址**：中间那些，**设备能用**

一个 /24 的网段有 256 个地址，去掉网络地址和广播地址，
剩下 254 个能给设备用。这就是"减 2"的由来。

> **什么时候不用减 2？**
> /31（点对点链路）按 RFC 3021 可以两个地址都给设备，
> 因为点对点不需要广播。/32 是单个主机地址，常用于环回口。
> 这两个是特例，配 GRE/IPsec 隧道和环回口时会用到，值得记住。

## 二、从一个真实需求开始算

假设要规划一个办公网络，需求是：

- 研发部 60 台设备
- 市场部 25 台设备
- 财务部 10 台设备
- 三个部门之间要隔离（不能直接互通）
- 网段从 `192.168.10.0/24` 里出

### 第一步：每个部门需要多大的块

关键在于**别按"设备数"选块，要按"设备数 + 网络地址 + 广播地址 + 余量"选**。

| 部门 | 设备数 | 最少需要 | 实际需要的块大小 |
|---|---|---|---|
| 研发 | 60 | 62 | **64**（/26 装不下，要 /25 的 128） |
| 市场 | 25 | 27 | **32**（/27） |
| 财务 | 10 | 12 | **16**（/28） |

这里就有第一个常见错误：有人看到 60 台，
算出 /26 有 62 个可用地址，觉得"够用"就选了 /26。

**62 个够 60 台，但没有余量。** 加一台打印机、一个 AP、
或者某天来一个实习生带笔记本，就满了。而扩网段意味着
重新规划、改所有设备的配置、可能还要改防火墙策略。

**我的经验法则：留 20% 以上余量，能整块对齐就整块对齐。**

所以研发部选 **/25**（126 个可用），而不是 /26。

### 第二步：按从大到小分配（关键顺序）

**必须从大块开始分。** 反过来会导致碎片化，
最后大块没地方放。

`192.168.10.0/24` 总空间 256 个地址。

```
研发部 /25：
  网络地址   192.168.10.0
  可用范围   192.168.10.1  ~ 192.168.10.126
  广播地址   192.168.10.127
  掩码       255.255.255.128
```

块大小 128，所以从 .0 开始占用到 .127。剩下 `.128 ~ .255`。

```
市场部 /27：
  起始       192.168.10.128
  块大小     32
  网络地址   192.168.10.128
  可用范围   192.168.10.129 ~ 192.168.10.158
  广播地址   192.168.10.159
  掩码       255.255.255.224
```

占用 .128 ~ .159。剩下 `.160 ~ .255`。

```
财务部 /28：
  起始       192.168.10.160
  块大小     16
  网络地址   192.168.10.160
  可用范围   192.168.10.161 ~ 192.168.10.174
  广播地址   192.168.10.175
  掩码       255.255.255.240
```

占用 .160 ~ .175。**还剩 .176 ~ .255（80 个地址）**，
留给以后扩展、访客网络、或者设备管理网段。

### 第三步：验证没有重叠

这一步别跳过。我见过不止一次"看起来分好了，
其实两个网段重叠"，结果路由表里出现冲突条目，
表现为"时通时不通"——这种毛病最难查。

```
研发部   0   ~ 127   (128 个)
市场部   128 ~ 159   (32 个)
财务部   160 ~ 175   (16 个)
预留     176 ~ 255   (80 个)
                 合计 256 ✓
```

**边界检查法**：每块的结束地址 + 1 = 下一块的起始地址，
且最后一块结束地址 + 1 = 网段总数（按最后一个八位组算）。

## 三、把掩码换算成位数（以及反过来）

这是必须练熟的基本功。

**掩码 → 位数**：数一下有多少个连续的 1。

```
255.255.255.0    = 11111111.11111111.11111111.00000000 = /24
255.255.255.128  = 11111111.11111111.11111111.10000000 = /25
255.255.255.192  = 11111111.11111111.11111111.11000000 = /26
255.255.255.224  = 11111111.11111111.11111111.11100000 = /27
255.255.255.240  = 11111111.11111111.11111111.11110000 = /28
```

**第四段的速算**（这是最常用的）：

| 掩码第四段 | 位数 | 块大小 | 可用地址 |
|---|---|---|---|
| 0 | /24 | 256 | 254 |
| 128 | /25 | 128 | 126 |
| 192 | /26 | 64 | 62 |
| 224 | /27 | 32 | 30 |
| 240 | /28 | 16 | 14 |
| 248 | /29 | 8 | 6 |
| 252 | /30 | 4 | 2 |
| 254 | /31 | 2 | 2（RFC 3021） |
| 255 | /32 | 1 | 1 |

**块大小 = 256 − 掩码第四段的值**。
比如 240 → 256−240 = 16；248 → 256−248 = 8。
记住这一条，比背表有用得多。

> **一个容易搞混的地方**：块大小是"这一段能装多少个地址"，
> 不是"这一段的起始地址可以是多少"。
> 起始地址必须是块大小的整数倍 —— /28 的块大小是 16，
> 所以合法的网络地址只有 .0、.16、.32、.48…… 以此类推。
> 把 /28 配成 192.168.10.20 是错的（会得到一个 16 的倍数向下取整的段）。

## 四、三个我见过的典型错误

### 错误一：把网络地址配到设备上

```
ip address 192.168.10.0 255.255.255.0    ← 错，这是网络地址
ip address 192.168.10.255 255.255.255.0  ← 错，这是广播地址
```

有些设备会直接拒绝配置并报错，有些**不报错但网不通**——
后者更折磨人，因为你会一直怀疑是路由或线缆问题。

### 错误二：网关不在同网段

```
设备配置    192.168.10.50/25
网关配置    192.168.10.130
```

`/25` 的范围是 .0 ~ .127，网关 .130 在**另一个网段**里。
设备根本 ARP 不到网关，表现是"能看不能通"——
本地同网段能互 ping，出网段全断。

### 错误三：网关选了段内第一个可用地址，但没检查冲突

习惯上网关用 `.1`。但如果 DHCP 池从 `.1` 开始分，
或者有人手工把某台服务器配成了 `.1`，就会 IP 冲突。

**我的习惯**：把网段的第一段留出来给网络设备。

```
192.168.10.0/25
  192.168.10.1             网关
  192.168.10.2 ~ .9        交换机 / AP / 打印机等基础设施（建议静态）
  192.168.10.10 ~ .99      DHCP 动态池
  192.168.10.100 ~ .126    服务器等需要固定 IP 的设备（静态）
```

这样"人"和"设备"的地址空间是分开的，
以后排障时不会对着一堆不清楚来历的 IP 发愣。

## 五、怎么验算（排障时最有用）

规划完不算完，**上设备前一定要验算**。三个命令：

**Windows**

```powershell
# 看本机 IP、掩码、网关，确认掩码没配错导致网段判断错误
ipconfig /all

# 看路由表里有没有意外的条目（比如两个网段重叠时会看到奇怪的 route）
route print -4
```

**Linux**

```bash
# 现在推荐 ip 而不是 ifconfig
ip -4 addr show
ip route show

# 想看某个 IP 属于哪个网段，用 ipcalc（很多发行版要单独装）
ipcalc 192.168.10.50/25
```

`ipcalc` 的输出直接把网络地址、广播地址、可用范围全列出来，
**是我最推荐的验算工具**：

```
$ ipcalc 192.168.10.50/25
Address:   192.168.10.50         11000000.10101000.00001010.0 0110010
Netmask:   255.255.255.128 = 25  11111111.11111111.11111111.1 0000000
Wildcard:  0.0.0.127             00000000.00000000.00000000.0 1111111
Network:   192.168.10.0/25       11000000.10101000.00001010.0 0000000
HostMin:   192.168.10.1          11000000.10101000.00001010.0 0000001
HostMax:   192.168.10.126        11000000.10101000.00001010.0 1111110
Broadcast: 192.168.10.127        11000000.10101000.00001010.0 1111111
Hosts/Net: 126
```

**注意 `Hosts/Net: 126`** —— 工具已经帮你减掉 2 了。
如果你自己算的是 128，说明你忘了减网络地址和广播地址。

## 六、我的规划清单

每次做地址规划，我按这个顺序走：

1. **数设备**，然后**乘 1.2 向上取整**（留余量）
2. **换算成最近的 2 的幂**（16 / 32 / 64 / 128）
3. **从大到小排**，大块优先分配
4. **算每块的网络地址、可用范围、广播地址**
5. **验算边界**：前一块结束 +1 = 后一块起始
6. **划出基础设施地址段**（网关、交换机、AP）
7. **留出足够空闲块**，并把规划写成文档
8. **上设备前用 `ipcalc` 复核**

第 7 条最容易被跳过，也最容易在半年后害到自己 ——
那时候你已经不记得某个 /28 是留给谁的了。

## 七、最后一点体会

子网划分本身不难，难的是**在压力下不出错**。

故障现场往往是这样：业务已经断了，主管站在你背后，
你要在几分钟内改一台核心设备的地址。
这时候如果对掩码换算没有到"条件反射"的程度，
就很容易把 240 写成 224 —— 一个数字之差，整个网段错位。

所以我的建议是：**平时就把换算练到不用想**。
练法很简单 —— 随便看到一台设备的 IP，
在心里说出它的网段、可用范围、广播地址。
一天练十次，一周就熟了。

**这类基本功的好处是：它不会过时。**
技术栈会换代，但 IPv4 的子网计算逻辑，
从 1981 年到现在一直没变。
