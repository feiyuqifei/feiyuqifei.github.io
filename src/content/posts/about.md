## 我是谁

一个同时在三条线上折腾的人：**Web 安全**、**硬件与嵌入式**、**效率工具**。

这三件事看起来不搭边，但对我来说是一条线：
都是**搞清楚一个系统到底是怎么运转的**。
只不过安全是找它运转时的漏洞，硬件是摸它的物理边界，
工具是把重复的事情变成一条命令。

白天写代码、拆设备、做实验；晚上把过程写下来。
这个站就是那些记录的归档。

## 为什么叫飞鱼

飞鱼这种生物有意思的地方在于：它既不属于天空，也不完全属于海洋。

它在水里游，靠的是鱼的本事；跃出水面的那一小段距离，
靠的是把胸鳍张开当翅膀用——**一种演化出来的、临时的飞行**。

我觉得技术人的状态很像：大部分时间在水下，
读源码、抓波形、翻数据手册，这些都不产生什么好看的东西；
偶尔跃出水面，做出一个能演示的作品，或者写出一篇有人看的文章。

但跃出去的高度，取决于潜下去的深度。
所以这个站叫**飞鱼**，标语是 **「潜得够深，才能跃出水面」** 。

## 这个站写什么

### 技术文章

安全研究、CTF 复盘、协议分析、源码阅读，以及大量踩坑记录。

我尽量不写"某某技术入门教程"那类东西——网上已经太多了。
更想写的是：**我遇到的具体问题，以及我是怎么定位到根因的**。
因为排查思路比结论可复用得多。

### 工具分享

真正用得上的软件、脚本和配置。

选入标准只有两条：**我自己在用**，以及**能说清楚它解决什么问题**。
清单类文章很多，我会给每个工具加上真实使用场景和踩过的坑。

### 关于写作的一点原则

- **不确定的事就说不确定**。技术文章里最怕的是把猜测写得很确定。
- **给可复现的步骤**。能贴命令就贴命令，能贴代码就贴代码。
- **标注适用范围**。某个技巧在 Windows 上有效，在 Linux 上可能完全不同。
- **写清楚失败的部分**。只写成功路径的文章会误导人。

## 技术栈

- **安全**：Burp Suite、mitmproxy、ffuf、sqlmap、Nuclei、CyberChef
- **编程**：Python、TypeScript、C（嵌入式方向）、PowerShell
- **硬件**：逻辑分析仪（PulseView / sigrok）、示波器、STM32 与 ESP32 平台

## 关于这个站

用 [Astro](https://astro.build) 静态生成，Markdown 写作，
托管在 GitHub Pages。没有数据库、没有后端、没有追踪 Cookie。

主题是手写的 CSS，没上框架——因为一个博客的复杂度不值得引入
构建链上多一层依赖。深浅色切换、全文搜索（Pagefind）、
RSS、KaTeX 公式都是纯静态实现。

源代码：[github.com/feiyuqifei](https://github.com/feiyuqifei)
